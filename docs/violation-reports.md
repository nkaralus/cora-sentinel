# Violation reports (`cora.security.violation/v1`)

`schema/violation.schema.json` is the contract (it is also committed to the `cora-security` repo; this copy is generated by `cora-report --write-schema` and pinned to the code by a test). A report says that a monitored task contacted
a blocklisted tracker or rogue address, and what Cora did about it. See
`examples/violation.example.json`.

## Fields

| Field | Meaning |
|---|---|
| `schema` | always `cora.security.violation/v1`. A breaking change gets a new id, never an edit. |
| `report_id` | random 128-bit id, unrelated to any local event |
| `observed_hour` | UTC, **truncated to the hour** |
| `task_ref` | 12 hex chars: `HMAC-SHA256(local secret salt, task name)`. Lets one reporter's repeat reports be recognised without revealing the task |
| `process` | executable basename, or `null` (null unless the operator opts in) |
| `violation.type` / `list` / `entry` | `tracker_domain` or `rogue_subnet`; which list; the exact entry that matched |
| `violation.destination` | `ip` (**only if public**, else `null`), `port`, `ip_class` |
| `violation.proto` | *optional.* How the connection spoke: `tcp`, `udp`, `quic`, `dns` or `unknown` |
| `violation.via` | *optional.* Which detector saw it: `syn_tap`, `udp_tap`, `sock_diag`, `proc_tcp`, or `unknown`. `dns_tap` is reserved: DNS goes through the UDP tap, so it reads `proto: dns`, `via: udp_tap` |
| `response` | `verdict`, whether it was `enforced`, any override `policy`, `model_confidence` (rounded to 0.1) |

## What is never in a report

Hostname, user, pid, virtual IP, cgroup/task name, command line, local ports or addresses, private
or LAN destination addresses, the model's free-text reason, exact timestamps.

The salt lives outside the report directory (`~/.config/cora/report_salt`, mode 0600 by default), so
a zipped report folder does not let anyone brute-force task names from `task_ref`.

## Validate

```
python3 -c "import json,jsonschema; s=json.load(open('schema/violation.schema.json')); \
jsonschema.validate(json.load(open('examples/violation.example.json')), s); print('ok')"
```

Reports are written locally and are never sent automatically; review, then file with
`gh issue create --repo nkaralus/cora-security --body-file <report>.md`.

`proto` and `via` were added in 0.8.6 as optional fields of `cora.security.violation/v1`: a report without them is still valid. The schema forbids other
extra keys, so a validator built from a copy of the schema older than 0.8.6 rejects a report that carries them. No consumer pins v1 yet; once one does,
a further addition needs a new id.
