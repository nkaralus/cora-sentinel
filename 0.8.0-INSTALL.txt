release-0.8.0/ holds the artifacts I built (Ubuntu 24.04, Python 3.12) and their SHA256SUMS. You do not have to trust them:
    packaging/build_release.sh        # needs: pip install build; writes dist/ and dist/SHA256SUMS
On the same toolchain it reproduces them byte for byte while HEAD is still d44785e (the epoch is the commit time, so a new
commit changes the bytes; SOURCE_DATE_EPOCH=<n> pins it).

Install the .deb (it does NOT start or enable the service):
    sudo dpkg -i release-0.8.0/cora-sentinel_0.8.0-1_all.deb
Read docs/packaging.md first: what install / upgrade / remove / purge do (removal takes the kernel floor out; purge keeps the audit logs).

DO NOT run packaging/lifecycle_test.sh on this host: it stops the cora-sentinel service and removes the kernel floor. It refuses unless
CORA_LIFECYCLE_TEST=disposable-machine is set and the machine shows no sign of running cora-sentinel. Use a throwaway VM.
